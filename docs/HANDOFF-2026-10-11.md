## 5. How to run things

Everything on a pod is one script, started over SSH, that writes `STATUS` and ends with a
`TERMINAL` line. Results go to the volume.

- **Pod**: RTX PRO 4500 in **EU-RO-1** (the volume lives there), network volume
  `96mu3d0s32` at `/workspace`, image
  `ghcr.io/selkies-project/selkies-egl-desktop:26.04-20260912122125` (pinned; the moving
  `26.04` tag segfaults Isaac Sim). Clone this repo to `/opt/behavior26`.
- **Submission run**, arm B, radio:

  ```bash
  SUBMISSION=1 ARMS=B EXPERIMENT=configs/experiments/003-radio-submission.yaml \
  ASSET_ID=turning_on_radio VOL_QUOTA_GB=250 MAX_HOURS=5 OUT=/workspace/submission2 \
  CKPT_B=/workspace/shot2/checkpoints/pi05_b1k_frozen_vlm_progress/armB/5999 \
  RUNPOD_POD_ID=<pod id> bash /opt/behavior26/scripts/eval_arms.sh
  ```

  Start it with `setsid nohup ... &` so it survives the SSH session. This exact command has
  not been run yet; the shoes submission run on 8 Oct used the same path.
- **Training** is `scripts/shot_one.sh`; **train → evaluate → compare on one pod** is
  `scripts/shot_two_chain.sh`. Each script's header explains its options.
- **Stopping pods**: a pod cannot terminate itself. `scripts/watchdog.sh`, run on a machine
  holding the account's RunPod key, terminates the pod when it sees `TERMINAL`, on 90
  minutes of silence, or at a deadline. Stop the watchdog before relaunching on a live pod,
  or a stale `TERMINAL` gets the pod terminated.

## 7. Things that cost time, so you do not repeat them

- `df` is useless on the network volume (it reports the whole cluster); use `du`. Pass
  `VOL_QUOTA_GB=250` or the evaluator thinks there is no room for videos.
- Do not push changes to `scripts/eval_arms.sh` while an evaluation runs: it checks out
  `origin/main` mid-run.
- Keep all of one evaluation on one GPU type so both arms are measured on the same hardware.
- Radio takes about 7.5 minutes per attempt on an RTX PRO 4500; shoes 15–45; coffee ~40.
- The simulator sometimes crashes mid-run and exits 0; the runner re-invokes for missing
  instances and keeps finished results.
- Only RunPod's proxy SSH works on this image (`<pod>-<n>@ssh.runpod.io`), and its output
  is noisy: tag lines and grep for them. Small files can be copied as tar + base64 with a
  sha256 check; large ones with `runpodctl send` / `receive`.
- Evaluation prompts must be the task names (patch `0003`), matching what training used.
